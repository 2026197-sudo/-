# 계명문화대학교 혁신지원사업단 성과관리 대시보드 — Netlify 배포용

**인사번호 + 본인 PIN으로 로그인**한 담당자만 대시보드를 보고, 본인 부서 지표의 실적만 입력할 수 있는 버전입니다.
전체 수정(기본 정보·문구·변경 이력·가입자 관리)은 관리자만 할 수 있습니다.
GitHub 저장소에 올리고 Netlify에 연결하면 자동으로 배포됩니다.

## 0. 로그인 설정 (관리자, 처음 한 번)

1. Netlify → 이 사이트 → **Project configuration → Environment variables → Add a variable**
2. Key: `KPI_ADMINS` · Value: `본인인사번호:PIN` (예: `2026000:123456`, PIN은 숫자 4~6자리. 관리자가 여럿이면 쉼표로 구분)
   - Scopes는 **All scopes**(또는 Functions 포함), Deploy contexts는 **All** 로 둡니다.
3. 저장한 뒤 **다시 배포**해야 적용됩니다 (Deploys → Trigger deploy).
4. 이 값은 GitHub(공개 저장소)에 올리지 않습니다. 관리자 인사번호로는 회원가입이 막혀 있어 다른 사람이 관리자를 사칭할 수 없습니다.

**담당자 가입**: 첫 화면에서 **처음 사용 (가입)** → 인사번호·이름·관리부서·PIN을 넣으면 바로 사용할 수 있습니다.
- 담당자는 가입한 부서가 관리하는 지표의 **현재값·상태·비고만** 저장됩니다(서버에서 확인하므로 화면을 조작해도 다른 부서 값은 바뀌지 않습니다).
- PIN은 해시로만 저장되고, 로그인은 12시간 유지됩니다. 로그인 실패가 15분에 10번을 넘으면 잠시 막힙니다.
- PIN 분실·잘못된 가입: 관리자가 실적 입력 화면의 **가입자 관리**에서 삭제하면 같은 인사번호로 다시 가입할 수 있습니다. 부서 변경도 여기서 합니다.
- 가입은 승인 없이 바로 되므로, 가끔 가입자 목록을 보고 모르는 가입자는 삭제하세요.

## 1. 배포하기 (처음 한 번, 약 10분)

### ① GitHub에 올리기
1. https://github.com 로그인 → 오른쪽 위 **+ → New repository**
2. Repository name: 예) `kmcu-kpi-dashboard` · **Private(비공개)** 선택 권장 → **Create repository**
3. 새 저장소 화면에서 **uploading an existing file** 클릭
4. 압축을 푼 `kmcu-kpi-netlify` 폴더 **안의 내용 전체**(`netlify.toml`, `package.json`, `public`, `netlify` 폴더 등)를 끌어다 놓기
   - 폴더째가 아니라 **폴더 안의 파일들**을 올려야 `netlify.toml`이 맨 위(루트)에 놓입니다.
5. 아래 **Commit changes** 클릭

### ② Netlify에 연결하기
1. https://app.netlify.com 접속 → **GitHub 계정으로 로그인**
2. **Add new site(또는 Add new project) → Import an existing project → GitHub**
3. 방금 만든 저장소 선택 (처음이면 Netlify가 GitHub 저장소 접근 권한을 요청합니다 → 허용)
4. 설정 화면은 `netlify.toml`이 자동으로 채우니 **그대로 두고 Deploy** 클릭
   - Publish directory: `public` · Functions directory: `netlify/functions`
5. 1~2분 뒤 `https://<임의이름>.netlify.app` 주소가 생깁니다.
   - **Site configuration → Change site name**에서 예) `kmcu-kpi`로 바꾸면 `https://kmcu-kpi.netlify.app`

### ③ 확인
- `https://주소/` → 대시보드
- `https://주소/admin.html` → 실적 입력 (로그인 필요)
- 실적을 한 번 저장해 보고, 다른 PC·휴대폰에서 대시보드에 반영되는지 확인하세요(최대 1분).

## 2. 쓰는 법

| 기능 | 방법 |
|---|---|
| 현황 보기 | 대시보드 주소 접속 → 로그인. **종합**에는 도넛 대시보드만, 부서별 현황·세부지표·유의사항·일정·필수확인사항은 메뉴를 눌러 봅니다 (1분마다 자동 갱신) |
| 실적 입력 | 메뉴의 **실적 입력** → 본인 부서 지표만 보임 → 값 수정 → **저장하기** (입력자는 로그인 정보로 자동 기록) |
| 잘못 저장했을 때 | 실적 입력 화면 아래 **변경 이력** → 원하는 시점의 **이 시점으로 되돌리기** |
| 부서별 현황 | 대시보드 메뉴 **부서별 현황** → 부서마다 담당 지표 진척률. 진척률 60% 미만(주의·부진)이거나 기간 경과율보다 낮은 지표(▼ 경과율 미달)가 있는 부서가 맨 앞에 '실적 확인필요 부서'로 표시 |
| 실적 엑셀 | 대시보드 오른쪽 위 **실적 엑셀파일** → '자율성과지표 현황' 양식의 .xlsx 내려받기 (달성률·비율반영 지표값은 수식이라 파일에서 값을 고치면 자동 재계산) |
| 요약보고 | 대시보드 오른쪽 위 **요약보고서** → 공유하기 / PDF 저장 / 출력 |
| 유의사항·일정·확인사항 고치기 | 실적 입력 화면의 **대시보드 문구 관리** → 추가·수정·삭제, 처리한 항목은 **완료** 체크 → **저장하기** |

**자동으로 바뀌는 항목**: 대시보드 '해석 시 유의사항'의 **자동** 표시 항목과 '지표 자동 점검' 목록은 지표 값과 상태로 자동 생성됩니다. 미입력·측정 전·부진(30% 미만)·기간 경과율보다 낮은 주의(30~60%) 지표가 나타나고, 값을 입력하거나 실적이 오르면 저절로 빠집니다. 실적 입력 화면에서 수치를 바꾸면 저장 전에도 '자동으로 표시되는 항목' 미리보기가 바로 바뀝니다.

**일정·필수확인사항 자동 연동**
- 다음 분기 실적 기준일과 측정기간 종료일은 **실적 기준일**(실적 입력의 기본 정보)에 맞춰 자동으로 표시됩니다. 예: 기준일이 8.31이면 '3분기 실적(9~11월) 기준일 11.30', 11.30이면 '4분기 … 기준일 · 측정기간 종료 2.28'.
- 측정 전 지표는 '○○ 측정' 일정으로 자동 표시되고, 상태를 '실적'으로 바꾸면 사라집니다.
- 날짜가 지난 일정은 '끝난 일정'으로 자동으로 접힙니다.
- 직접 입력한 일정·실적 파일 확인사항에 **연결 지표**를 고르면, 그 지표가 '실적'으로 입력되는 순간 **자동 완료**됩니다. (예: '유지율 계 수식 수정' ↔ 재학생 수 유지율)

- **여러 팀이 동시에 입력해도 안전합니다.** 화면을 연 뒤 다른 팀이 먼저 저장했다면, 저장할 때 최신 자료를 다시 받아 **내가 바꾼 항목만** 합쳐서 저장합니다. 다른 팀이 입력한 값은 덮어쓰지 않습니다.
- 저장·되돌리기를 할 때마다 직전 자료가 **변경 이력에 최근 100개까지** 자동 보관됩니다. 되돌리기도 이력에 남으므로 다시 되돌릴 수 있습니다.
- 상태 값: **실적**(진척률 계산) · **측정 전**(학년도 말 조사 등, 진척률 미표시) · **미입력**(지수 계산에서 0)

## 3. 자료는 어디에 저장되나요?

- 웹에서 입력한 실적은 **Netlify Blobs**(이 사이트 전용 저장소)에 저장됩니다. Netlify 무료 플랜에 포함되어 있고 따로 설정할 것이 없습니다.
- 가입자 명단(인사번호·이름·부서·PIN 해시)도 같은 저장소에 보관됩니다.
- `netlify/lib/seed.mjs`는 **처음 배포했을 때의 기본 자료**입니다. 웹에서 한 번이라도 저장한 뒤에는 저장소의 자료가 우선입니다.
- 실적 자료는 로그인해야만 받을 수 있습니다(공개 `data.json` 없음).
- 정기 보관이 필요하면 실적 입력 화면의 **현재 자료 내려받기(JSON)**로 분기마다 파일을 받아 두세요.

## 4. 화면·문구를 고치고 싶을 때

GitHub 저장소에서 파일을 열어 연필(✏️) 아이콘으로 수정 → **Commit changes**하면 Netlify가 1~2분 안에 자동으로 다시 배포합니다.

| 고칠 내용 | 위치 |
|---|---|
| 유의사항·일정·필수확인사항·정의서 정정 사항 문구 | 실적 입력 화면의 **대시보드 문구 관리**에서 바로 고칩니다(코드 수정 불필요). |
| 색상 구간(30·60·90%) | 첫 배포 **전**에 `netlify/lib/seed.mjs`의 `meta.thresholds` 수정 |
| 디자인 | `public/css/style.css` |
| 로고 | `public/img/logo.png` (같은 이름으로 교체) |

## 5. 계산 방식 (자율성과지표 정의서 기준)

- 세부지표 진척률 = 현재값 ÷ 2차년도('26) 목표 × 100
- 혁신지수 = Σ (현재값 ÷ 3차년도('27) 목표 × 100 × 반영비중)
- 지수 진척률 = 현재 지수 ÷ 2차년도 목표 지수 × 100 · 전체 평균 = 4개 지수 진척률 평균
- 색상: 90% 이상 우수 · 60~90% 양호 · 30~60% 주의 · 30% 미만 부진
- 도넛 위 눈금: 실적 기준일(현재 2026.08.31)까지의 측정기간 경과율(참고)

## 6. 공개 범위 안내

- 로그인 전에는 로그인·가입 화면만 보이고, 실적 자료는 로그인한 사람에게만 전달됩니다.
- 가입 화면에는 부서 이름 목록만 공개됩니다.
- 누군가 잘못 수정해도 관리자가 **변경 이력**으로 되돌릴 수 있습니다.

## 7. 폴더 구성

```
kmcu-kpi-netlify/
├─ netlify.toml              Netlify 배포 설정 (자동 인식)
├─ package.json              서버리스 함수가 쓰는 패키지(@netlify/blobs) — Netlify가 자동 설치
├─ netlify/
│  ├─ functions/api.mjs      로그인·가입, 자료 조회·저장, 변경 이력, 가입자 관리 API (/api/*)
│  └─ lib/seed.mjs           첫 배포용 기본 자료
└─ public/                   화면 (index.html, admin.html, css, js, img)
```

## 8. 배포가 안 될 때

- Netlify **Deploys** 탭에서 실패한 배포를 눌러 로그를 확인하세요.
- `netlify.toml`이 저장소 **맨 위(루트)**에 있는지 확인하세요. 폴더째 올렸다면 Netlify 설정의 **Base directory**에 그 폴더 이름(예: `kmcu-kpi-netlify`)을 적으면 됩니다.
- 로그인이 안 되면 `KPI_ADMINS` 환경 변수를 넣은 뒤 다시 배포했는지 확인하세요. `https://주소/api/health`의 `admins` 값이 1 이상이면 설정된 것입니다.
- 자료를 불러오지 못하면 `https://주소/api/health`를 열면 저장소 연결 상태(`"store":"connected"`면 정상)와 오류 내용을 볼 수 있습니다.
- 그래도 원인을 모르겠으면 Netlify **Logs → Functions → api**에서 오류를 확인하세요.
